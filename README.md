# 🎮 YORR Arcade

**노트북이 화면, 휴대폰이 컨트롤러**인 웹 미니게임 모음.
노트북에서 4자리 코드를 발급하고 폰으로 접속하면, 폰을 휘두르거나 기울여 게임을 조종한다.
게임 5종 · 그중 3종은 방 코드로 **온라인 1:1 대전**까지 된다.

> 팀 본 프로젝트(Spring + WebRTC)로 가기 전, 핵심(센서 입력 · 방/입장 · 실시간 동기화)을
> 빠르게 검증하는 개인 탐색용 스파이크입니다. 속도 우선이라 실시간은 Socket.IO 로 구성했습니다.
> 앱 설치 없이 브라우저만으로 돌아갑니다.

## 🎮 게임 5종

게임 선택 화면(GameHub)에서 카드로 고른다. 각 게임은 `client/src/games/<게임>/` 아래에 있고,
게임 루프는 `useRef`, UI 노출값만 `useState` 로 관리한다(상태관리 라이브러리 없음).

| 게임 | 설명 | 입력 | 온라인 1:1 |
|------|------|------|:---:|
| 🎲 **요트 다이스** | 진짜로 굴러가는 3D 주사위 5개로 12라운드 족보 채우기 | 폰 흔들기 / 버튼 | — (N인 동시 라운드 방) |
| 🏓 **핑퐁 스매시** | **3D** 코트에서 타이밍 맞춰 스매시. 봇 난이도 3단계 | 폰 스윙 / 키보드 | ✅ |
| 🎵 **리듬 탭** | 내려오는 네온 노트를 Perfect·콤보로 | 화면 탭 / 폰 스윙 / 키보드 `D F J K` | ✅ |
| 🤠 **황야의 퀵드로우** | 석양의 결투 — 신호등이 초록이 되면 먼저 뽑기 (3발 승부) | 폰 휘두르기 / 탭 / 키보드 `Space` | ✅ |
| 🗡️ **기술스택 슬래셔** | 날아오는 기술 로고를 광선검으로 베기(60초) | 폰 기울여 조준 / 마우스 스와이프 | — |

> **외부 이미지·폰트를 하나도 안 쓴다.** 로고·텍스처·그림자·마스코트까지 전부 코드로 그린다
> (Canvas 2D · Three.js · SVG).

## 📱 폰을 컨트롤러로 쓰기

이 프로젝트의 중심 구조. 게임 화면은 노트북에만 그리고, 폰은 **센서 입력만** 보낸다.

```
[폰]  가속도/자이로 감지 ──ctrl:swing──▶ [서버]  같은 페어링 방으로 중계 ──▶ [노트북]  판정·렌더
        ▲                                                                        │
        └──────────────── ctrl:hit (진동 피드백) ◀───────────────────────────────┘
```

1. 노트북 허브에서 **[폰 연결 코드 발급]** → 4자리 코드가 뜬다
2. 폰 브라우저로 같은 주소 접속 → 코드 입력 (또는 `?ctrl=CODE` 로 바로 연결)
3. 폰이 컨트롤러 화면으로 바뀐다. **노트북이 고른 게임에 맞춰 폰 UI 도 같이 바뀐다**(`disp:game`)

- **한 노트북에 폰 여러 대**를 붙일 수 있다 (퀵드로우는 2대면 폰끼리 결투)
- 스윙 감지: `DeviceMotion` 가속도 크기가 **14 m/s²** 를 넘으면 스윙. 중력 성분은 저역통과로 빼고,
  히스테리시스로 한 번의 휘두름이 여러 번 잡히는 것을 막는다 →
  [useSwing.ts](client/src/games/pingpong/useSwing.ts)
- 슬래셔 조준: `DeviceOrientation` 의 yaw·pitch 를 0~1 좌표로 정규화해 ~35Hz 로 전송
- 입력 지연은 계속 측정해서(왕복 ping 중앙값) 25ms 를 넘을 때만 화면에 경고를 띄운다 →
  [latency.ts](client/src/net/latency.ts)

> 센서 API 는 **HTTPS 에서만** 동작한다. 그래서 로컬 개발도 https 로 띄운다(아래 실행 방법).

> **요트 다이스** 의 주사위는 키프레임 애니메이션이 아니라 **직접 만든 강체 물리**로 굴린다.
> 나올 눈은 이미 정해져 있는데 물리는 그걸 모르므로, "화면에 안 그리고 한 번 굴려 본 뒤
> 그 자세에서 목표 눈이 위로 오도록 주사위 눈을 다시 붙이고(정육면체 대칭이라 궤적이 안 바뀐다)
> 되감아 진짜로 굴리는" 방식을 쓴다 → 마지막에 억지로 돌려 맞추는 스냅이 0.
> 규칙(순수 계산)은 [client/src/games/yacht/physics.ts](client/src/games/yacht/physics.ts),
> 3D 무대는 [client/src/games/yacht/dice3d.ts](client/src/games/yacht/dice3d.ts).

> **기술스택 슬래셔** 는 서버·소켓 없이 도는 순수 클라이언트 게임이다. Canvas 2D 로 오브젝트·블레이드 궤적을
> 그리고, 벤 스택을 분야(FE·BE·Infra·AI)별로 모아 **개발자 유형**을 판정한다.
> 로고는 외부 에셋 없이 전부 캔버스로 직접 그린다. 코드: [client/src/games/slasher/](client/src/games/slasher/)

### 서버가 다루는 방 5종

서버는 게임 규칙을 모른다. 방을 나누고 메시지를 중계할 뿐이고, 판정은 화면 쪽이 한다.

| 접두어 | 용도 |
|---|---|
| `pair:` | 노트북 1대 ↔ 폰 N대 컨트롤러 페어링 |
| `room:` | 요트 다이스 — N인 동시 라운드 |
| `pp:` · `rt:` · `rx:` | 핑퐁 · 리듬탭 · 퀵드로우 온라인 1:1 |

온라인 1:1 은 **호스트가 권위를 갖고** 시뮬레이션을 돌려 상태를 중계하고,
게스트는 수신 사이를 추측항법으로 보간한다. 방 상태는 서버 메모리에만 있다(재시작 시 초기화).

## 🚀 실행하기

### 방법 ① 원클릭 (추천)

- **같은 와이파이/핫스팟**에서 플레이 → **`로컬플레이.bat`** 더블클릭
  - 서버(3001) + 웹(5173, https)이 뜨고, 폰 접속 주소(`https://172.20.10.x:5173/`)가 표시됨.
- **멀리 있는 친구와 온라인** 플레이 → **`온라인플레이.bat`** 더블클릭
  - 빌드 후 서버가 앱+소켓을 서빙하고, ngrok 공개주소(`https://xxxx.ngrok-free.dev`)를 발급 → 그 주소를 공유.
- (`.ps1` 을 직접 우클릭 실행하면 Windows 실행정책 때문에 창이 닫힐 수 있어, 반드시 `.bat` 을 쓰세요.)

### 방법 ② 터미널 2개 직접

```bash
# 터미널 1 — 실시간 서버
cd server
npm install      # 최초 1회
npm run dev      # 포트 3001

# 터미널 2 — 웹(클라이언트)
cd client
npm install      # 최초 1회
npm run dev      # https://localhost:5173
```

> 웹(5173)은 `/socket.io` 요청을 서버(3001)로 **프록시**합니다(`vite.config.ts`).
> 덕분에 폰은 **5173 한 포트만** 열면 실시간 통신까지 됩니다. (CORS/추가 포트 불필요)

## 📶 폰이 접속 안 될 때 (핫스팟)

학교/회사 와이파이는 **기기 간 통신을 막아서(AP 격리)** 폰↔PC 접속이 안 될 수 있습니다.
그래서 **폰 핫스팟**을 쓰는 게 가장 확실합니다.

1. **폰에서 개인용 핫스팟 켜기**
2. **노트북 Wi-Fi 를 그 핫스팟에 연결**
3. 위 실행 스크립트 실행 → 뜨는 **`https://172.20.10.x:5173/`** 주소를 폰 브라우저에 입력
4. 인증서 경고 → 계속 진행 (아이폰: "세부사항 → 웹사이트 방문")

> 💾 **데이터 걱정 X**: 폰↔노트북 통신은 핫스팟 로컬 링크 안에서만 오가고 셀룰러를 안 탑니다.
> 게임도 노트북이 로컬로 서빙하므로 **플레이 중 데이터 사용은 사실상 0**입니다.
> (걱정되면 Windows Wi-Fi 설정에서 그 핫스팟을 "종량제 연결"로 켜두면 백그라운드 사용도 차단됩니다.)

## 🕹️ 요트 다이스 — 온라인 방 플레이

> 나머지 4종은 허브에서 카드를 눌러 바로 시작한다. 조작은 각 게임 시작 화면에 안내가 뜬다.

1. **닉네임 입력** → **[방 만들기]** (또는 친구가 준 링크/코드로 **[참가하기]**)
2. **대기실**: 입장코드·링크를 친구에게 공유. 다 모이면 방장이 **[게임 시작]**
3. **게임 (동시 플레이)**: 라운드마다 모두가 각자
   - **[🎲 굴리기]** 버튼(또는 폰 흔들기)으로 굴림 — 주사위가 **오른쪽에서 굴러 떨어져** 트레이에 놓임
   - 남기고 싶은 주사위를 **눌러 상단 KEEP 칸으로 올림**(다시 누르면 트레이로 내려옴), 나머지만 다시 굴림 (**최대 3번**)
   - 오른쪽 **점수표에서 내 열의 칸을 눌러** 확정 (칸마다 "지금 넣으면 몇 점"인지 라임색으로 미리 보임)
   - 모두가 확정하면 다음 라운드로. **12라운드** 후 종료
   - 하단에서 **민감도(안정/보통/민감) · 모션 · 진동 · 사운드** 를 켜고 끌 수 있음
4. **결과**: 총점 순위 표시

### 📖 점수 규칙 (한국에서 통용되는 요트다이스 룰)

윗줄:
- **1~6**: 해당 눈의 합 (예: `4`는 4가 나온 개수 × 4)
- **보너스**: 윗줄(1~6) 합이 **63점 이상**이면 **+35점**

아랫줄:
| 족보 | 조건 | 점수 |
|------|------|------|
| 초이스 | 아무 조합 | 주사위 5개 합 |
| 포카드 | 같은 눈 4개 이상 | 주사위 5개 합 |
| 풀하우스 | 3개 + 2개 | 주사위 5개 합 |
| S.스트레이트 | 4개 연속 | 15점 |
| L.스트레이트 | 5개 연속 | 30점 |
| 요트 | 5개 모두 같음 | 50점 |

> 참고: 1938년 원조 Yacht 룰과 한국식(야찌 보너스 포함) 룰에 차이가 있어, 한국 플레이어에게
> 익숙한 방식(스몰/라지 스트레이트 · 윗줄 63점 보너스)을 채택했습니다.
> 규칙은 [game/yacht.ts](client/src/game/yacht.ts) 한 곳에 모여 있어 쉽게 바꿀 수 있습니다.

## 🧩 기술 스택

| 영역 | 선택 | 이유 |

| 상태 저장 | 서버 메모리 | 프로토타입이라 DB 생략 (재시작 시 초기화) |
