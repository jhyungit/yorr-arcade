# 🎮 YORR Arcade

**노트북이 화면, 휴대폰이 컨트롤러**인 웹 미니게임 모음.
노트북에서 4자리 코드를 발급하고 폰으로 접속하면, 폰을 휘두르거나 기울여 게임을 조종한다.
게임 5종 · 요트는 **최대 6인 턴제 온라인**, 3종은 방 코드로 **온라인 1:1 대전**까지 된다.

> 팀 본 프로젝트(Spring + WebRTC)로 가기 전, 핵심(센서 입력 · 방/입장 · 실시간 동기화)을
> 빠르게 검증하는 개인 탐색용 스파이크입니다. 속도 우선이라 실시간은 Socket.IO 로 구성했습니다.
> 앱 설치 없이 브라우저만으로 돌아갑니다.

## 🎮 게임 5종

게임 선택 화면(GameHub)에서 카드로 고른다. 각 게임은 `client/src/games/<게임>/` 아래에 있고,
게임 루프는 `useRef`, UI 노출값만 `useState` 로 관리한다(상태관리 라이브러리 없음).

| 게임 | 설명 | 입력 | 온라인 대전 |
|------|------|------|:---:|
| 🎲 **요트 다이스** | 진짜로 굴러가는 3D 주사위 5개로 12라운드 족보 채우기 | 폰 흔들기 / 버튼 | ✅ **최대 6인 턴제** |
| 🏓 **핑퐁 스매시** | **3D** 코트에서 타이밍 맞춰 스매시. 봇 난이도 3단계 | 폰 스윙 / 키보드 | ✅ |
| 🎵 **리듬 탭** | 내려오는 네온 노트를 Perfect·콤보로 | 화면 탭 / 폰 스윙 / 키보드 `D F J K` | ✅ |
| 🤠 **황야의 퀵드로우** | 석양의 결투 — 신호등이 초록이 되면 먼저 뽑기 (3발 승부) | 폰 휘두르기 / 탭 / 키보드 `Space` | ✅ |
| 🗡️ **기술스택 슬래셔** | 날아오는 기술 로고를 광선검으로 베기(60초) | 폰 기울여 조준 / 마우스 스와이프 | — |

> **외부 이미지·폰트를 하나도 안 쓴다.** 로고·텍스처·그림자·마스코트까지 전부 코드로 그린다
> (Canvas 2D · Three.js · SVG).

## 📱 폰을 컨트롤러로 쓰기

이 프로젝트의 중심 구조. 게임 화면은 노트북에만 그리고, 폰은 **센서 입력만** 보낸다.

```
[폰]  가속도/자이로 감지 ──ctrl:swing──▶ [서버]  같은 페어링 방으로 중계 ──▶ [노트북]  판정·렌더
        ▲                                                                        │
        └──────────────── ctrl:hit (진동 피드백) ◀───────────────────────────────┘
```

1. 노트북 허브에서 **[폰 연결 코드 발급]** → 4자리 코드가 뜬다
2. 폰 브라우저로 같은 주소 접속 → 코드 입력 (또는 `?ctrl=CODE` 로 바로 연결)
3. 폰이 컨트롤러 화면으로 바뀐다. **노트북이 고른 게임에 맞춰 폰 UI 도 같이 바뀐다**(`disp:game`)

- **한 노트북에 폰 여러 대**를 붙일 수 있다 (퀵드로우는 2대면 폰끼리 결투)
- **요트만 폰이 "양방향"이다.** 다른 게임은 폰이 휘두르기만 보내면 되지만, 요트는
  킵·점수 선택이 게임의 본체라 그것만으로는 결국 노트북 마우스를 잡아야 한다.
  그래서 노트북이 화면 상태를 폰에 내려보내고(`disp:yacht`) 폰이 조작을 올려보낸다
  (`ctrl:keep`·`ctrl:select`·`ctrl:score`·`ctrl:react`) → **폰만으로 한 턴을 끝낼 수 있다.**
  폰이 스스로 판정하지 않고 노트북에 "요청"만 하므로 두 화면이 어긋나지 않는다.
  규약: [ctrlProtocol.ts](client/src/games/yacht/ctrlProtocol.ts)
- 스윙 감지: `DeviceMotion` 가속도 크기가 **14 m/s²** 를 넘으면 스윙. 중력 성분은 저역통과로 빼고,
  히스테리시스로 한 번의 휘두름이 여러 번 잡히는 것을 막는다 →
  [useSwing.ts](client/src/games/pingpong/useSwing.ts)
- 슬래셔 조준: `DeviceOrientation` 의 yaw·pitch 를 0~1 좌표로 정규화해 ~35Hz 로 전송
- 입력 지연은 계속 측정해서(왕복 ping 중앙값) 25ms 를 넘을 때만 화면에 경고를 띄운다 →
  [latency.ts](client/src/net/latency.ts)

> 센서 API 는 **HTTPS 에서만** 동작한다. 그래서 로컬 개발도 https 로 띄운다(아래 실행 방법).

> **요트 다이스** 의 주사위는 키프레임 애니메이션이 아니라 **직접 만든 강체 물리**로 굴린다.
> 나올 눈은 이미 정해져 있는데 물리는 그걸 모르므로, "화면에 안 그리고 한 번 굴려 본 뒤
> 그 자세에서 목표 눈이 위로 오도록 주사위 눈을 다시 붙이고(정육면체 대칭이라 궤적이 안 바뀐다)
> 되감아 진짜로 굴리는" 방식을 쓴다 → 마지막에 억지로 돌려 맞추는 스냅이 0.
> 규칙(순수 계산)은 [client/src/games/yacht/physics.ts](client/src/games/yacht/physics.ts),
> 3D 무대는 [client/src/games/yacht/dice3d.ts](client/src/games/yacht/dice3d.ts).
>
> 물리는 **노드에서 그냥 돌아가므로**(three 의 수학만 씀) 손맛을 눈대중이 아니라 재서 맞췄다.
> 500판을 돌려 "구르는 시간 · 알당 이동거리 · 반대쪽 벽까지 가는 비율 · 초반 회전" 을 뽑는다.
> 처음엔 1.08초 · 1.43(판 가로는 2.6) 으로 던지자마자 멈췄다. 범인은 던지는 세기가 아니라
> **감쇠**였고, 낮춰서 **1.52초 · 2.58 · 83%** 가 됐다.
>
> - **회전 체감은 최고 회전수가 아니라 "초반 0.6초의 평균 회전"** 이 정한다. 감쇠가 세면
>   순간 100rad/s 를 찍어도 금방 죽어 오히려 느리게 느껴진다. 이동 감쇠와 회전 감쇠를
>   따로 둬서 "오래 굴러가되 팽이처럼은 안 돌게" 맞췄다.
> - **판 밖으로 날아가던 버그**: 보이는 테두리가 0.3 뿐인데 벽 충돌을 그 높이까지만 봐서,
>   세게 던지면 테두리를 넘어 밖으로 날아갔다 다시 들어왔다. 진입은 원래 테두리를
>   넘어와야 하므로, **판 안에 들어온 뒤부터** 높은 벽을 세워 막았다 (500판 이탈 0).
> - 화면은 120Hz 물리를 그대로 그리지 않고 **직전 스텝과 보간해서** 그린다
>   (60Hz 화면에서 프레임마다 밟는 스텝 수가 2·3·2·1 로 흔들려 떨림으로 보이기 때문).

> **기술스택 슬래셔** 는 서버·소켓 없이 도는 순수 클라이언트 게임이다. Canvas 2D 로 오브젝트·블레이드 궤적을
> 그리고, 벤 스택을 분야(FE·BE·Infra·AI)별로 모아 **개발자 유형**을 판정한다.
> 로고는 외부 에셋 없이 전부 캔버스로 직접 그린다. 코드: [client/src/games/slasher/](client/src/games/slasher/)

### 서버가 다루는 방 5종

| 접두어 | 용도 | 권위 |
|---|---|---|
| `pair:` | 노트북 1대 ↔ 폰 N대 컨트롤러 페어링 | 중계만 |
| `room:` | 요트 다이스 — **최대 6인 턴제** | **서버** |
| `pp:` · `rt:` · `rx:` | 핑퐁 · 리듬탭 · 퀵드로우 온라인 1:1 | 호스트 |

- **온라인 1:1** 은 **호스트가 권위를 갖고** 시뮬레이션을 돌려 상태를 중계하고,
  게스트는 수신 사이를 추측항법으로 보간한다. 서버는 규칙을 모르고 중계만 한다.
- **요트 방(`room:`)은 서버가 권위를 갖는다.** 턴제·관전 때문이다 —
  주사위를 서버가 굴려야 6명 화면에 같은 눈이 뜨고, 점수 계산도 서버가 해서
  클라가 보낸 숫자를 믿지 않는다. 좌석 id 는 `p1`~`p6` 로 고정하고,
  재접속은 입장 때 발급한 비밀 `token` 으로 원래 자리를 되찾는다.

방 상태는 서버 메모리에만 있다(재시작 시 초기화).

## 🚀 실행하기

### 방법 ① 원클릭 (추천)

- **같은 와이파이/핫스팟**에서 플레이 → **`로컬플레이.bat`** 더블클릭
  - 서버(3001) + 웹(5173, https)이 뜨고, 폰 접속 주소(`https://172.20.10.x:5173/`)가 표시됨.
- **멀리 있는 친구와 온라인** 플레이 → **`온라인플레이.bat`** 더블클릭
  - 빌드 후 서버가 앱+소켓을 서빙하고, ngrok 공개주소(`https://xxxx.ngrok-free.dev`)를 발급 → 그 주소를 공유.
- (`.ps1` 을 직접 우클릭 실행하면 Windows 실행정책 때문에 창이 닫힐 수 있어, 반드시 `.bat` 을 쓰세요.)

### 방법 ② 터미널 2개 직접

```bash
# 터미널 1 — 실시간 서버
cd server
npm install      # 최초 1회
npm run dev      # 포트 3001

# 터미널 2 — 웹(클라이언트)
cd client
npm install      # 최초 1회
npm run dev      # https://localhost:5173
```

> 웹(5173)은 `/socket.io` 요청을 서버(3001)로 **프록시**합니다(`vite.config.ts`).
> 덕분에 폰은 **5173 한 포트만** 열면 실시간 통신까지 됩니다. (CORS/추가 포트 불필요)

## ☁️ 배포 (고정 주소로 상시 운영)

`온라인플레이.bat`(ngrok)은 **내 노트북이 켜져 있어야** 하고 주소가 매번 바뀐다.
"항상 같은 주소로 들어와서 플레이"를 하려면 클라우드에 올린다.

**서비스 하나만 배포하면 된다.** Node 서버가 빌드된 앱(`client/dist`)과 소켓을 같은
포트로 서빙하므로, 클라이언트의 `io()`(주소 없이 = same-origin)가 그대로 동작하고
CORS 설정도 필요 없다. 프론트를 Vercel 등에 따로 올리면 이 구조가 깨진다.

```
npm run build   # client 의존성 설치 → 앱 빌드 → server 의존성 설치
npm start       # 서버가 앱 + 소켓을 PORT 로 서빙
npm test        # 서버를 띄워 소켓 여러 개를 붙이는 통합 테스트
```

### 처음 한 번만

1. [Render](https://render.com) 가입 → **New → Blueprint** → 이 저장소 선택
   (루트의 [render.yaml](render.yaml) 을 읽어 자동 설정된다)
2. 대시보드 → **Settings → Deploy Hook** 의 URL 복사
3. GitHub 저장소 → **Settings → Secrets and variables → Actions** →
   `RENDER_DEPLOY_HOOK_URL` 로 등록
4. 발급된 `https://<이름>.onrender.com` 주소를 공유하면 끝.
   도메인을 샀다면 Render 에서 커스텀 도메인으로 연결(CNAME)하면 된다 — **도메인은 필수가 아니다.**

### 배포 흐름 (CI/CD)

```
develop 작업 ─PR─▶ CI(빌드+테스트) ─통과─▶ main 머지 ─▶ CI 재검사 ─통과─▶ Render 배포
                        │                                    │
                      실패 → 머지 못 함                    실패 → 배포 안 함
```

- **CI** = 타입체크·빌드·통합테스트 ([.github/workflows/ci.yml](.github/workflows/ci.yml))
- **CD** = 그게 통과했을 때만 Render Deploy Hook 을 호출
- Render 의 Auto-Deploy 는 **일부러 껐다**(`autoDeploy: false`). Auto-Deploy 는 push 만
  보고 CI 결과를 모르기 때문에, 켜 두면 테스트가 빨간불인 커밋도 배포된다.

### 깨졌을 때

| 어디서 깨지나 | 어떻게 되나 |
|---|---|
| CI 검사 실패 | **배포가 아예 안 돈다.** 이미 배포된 버전이 그대로 서비스됨 |
| Render 빌드 실패 | Render 가 새 버전을 안 띄우고 **이전 버전을 계속 서빙** |
| 배포는 됐는데 버그 | 자동으로 안 잡힌다 → 아래 롤백 |

즉 앞의 둘은 "롤백"이 아니라 **애초에 안 바뀌는 것**이다. 진짜 롤백이 필요한 건 세 번째뿐.

```bash
# 방법 ① git 으로 되돌리기 (권장 — 히스토리에 남고 CI 를 다시 통과한다)
git revert <문제커밋> && git push origin main

# 방법 ② 급할 때: Render 대시보드 → Deploys → 이전 배포의 "Rollback"
```

### 무료 플랜에서 알아둘 것

- **인스턴스를 늘리면 안 된다.** 방 상태(`rooms` Map)가 프로세스 메모리에 있어서,
  2개로 늘리면 서로 다른 인스턴스에 붙은 사람끼리 같은 방을 못 본다
  (증상: 코드를 맞게 넣었는데 "방을 찾을 수 없어요"). 키우려면 Redis 어댑터가 먼저다.
- **유휴 상태로 두면 잠든다** → 첫 접속이 수십 초 걸린다(cold start).
- **재시작하면 진행 중인 방이 사라진다**(메모리 저장). 약속해서 노는 용도면 문제없다.
- 무료 티어 조건은 자주 바뀌니 가입 전에 현재 조건을 확인할 것.

## 📶 폰이 접속 안 될 때 (핫스팟)

학교/회사 와이파이는 **기기 간 통신을 막아서(AP 격리)** 폰↔PC 접속이 안 될 수 있습니다.
그래서 **폰 핫스팟**을 쓰는 게 가장 확실합니다.

1. **폰에서 개인용 핫스팟 켜기**
2. **노트북 Wi-Fi 를 그 핫스팟에 연결**
3. 위 실행 스크립트 실행 → 뜨는 **`https://172.20.10.x:5173/`** 주소를 폰 브라우저에 입력
4. 인증서 경고 → 계속 진행 (아이폰: "세부사항 → 웹사이트 방문")

> 💾 **데이터 걱정 X**: 폰↔노트북 통신은 핫스팟 로컬 링크 안에서만 오가고 셀룰러를 안 탑니다.
> 게임도 노트북이 로컬로 서빙하므로 **플레이 중 데이터 사용은 사실상 0**입니다.
> (걱정되면 Windows Wi-Fi 설정에서 그 핫스팟을 "종량제 연결"로 켜두면 백그라운드 사용도 차단됩니다.)

## 🕹️ 요트 다이스 — 최대 6인 턴제 온라인 플레이

> 나머지 4종은 허브에서 카드를 눌러 바로 시작한다. 조작은 각 게임 시작 화면에 안내가 뜬다.

허브에서 요트 카드를 누르면 **[방 만들기] · [게임 참여] · [혼자 하기]** 를 고른다.

1. **방 만들기** → **6자리 초대 코드**가 발급되고 바로 대기실에 들어간다.
   참가자는 **[게임 참여]** 에서 그 코드를 넣으면 입장 (`?room=CODE` 링크로도 바로 입장).
2. **대기실**: 좌석 6칸이 보인다. 코드를 탭하면 복사. 다 모이면 방장이 **[게임 시작]**
3. **게임 (턴제)**: 보드는 화면에 하나뿐이고 **지금 차례인 사람의 주사위를 모두가 같이 본다.**
   - 내 차례: **[굴리기]**(또는 폰 흔들기) → 남길 주사위를 **탭해 KEEP 레일로 올림** → 나머지만 다시 굴림 (**최대 3번**)
   - **점수표에서 칸을 고르고**(금색 = 지금 넣으면 몇 점) 아래 **큰 버튼으로 확정** — 오탭으로 칸을 날리지 않게 2단계
   - 남의 차례: 조작이 잠기고 **관전**. 굴러가는 주사위 · KEEP · 점수판이 실시간으로 따라온다
   - 요트·라지 스트레이트 같은 **족보 콜아웃**은 방 전체에 같이 뜬다 (같이 놀라는 게 재미)
   - **차례당 45초.** 시간을 다 쓰면 서버가 대신 굴리고 **가장 점수가 높은 칸**에 기록한다
     (한 사람이 폰을 놓고 가도 판이 멈추지 않는다. "시간초과·자동" 으로 표시됨)
   - 리액션 버튼(👍😂😮👏🎉)으로 남의 차례에도 참견할 수 있다
4. **결과**: **12라운드 × 인원**을 다 채우면 총점 순위. 1등은 금색, 각 줄에 "제일 크게 먹은 칸"도 표시.
   방장이 **[다시 하기]** 를 누르면 같은 방으로 대기실로 돌아간다.

**연결이 끊겨도 자리를 지킨다.** 폰이 잠기거나 새로고침해도 입장 때 받은 토큰으로
원래 좌석·점수판을 그대로 되찾는다. 그동안 내 차례가 오면 서버가 8초만 기다린 뒤 대신 플레이한다.
